# CLAUDE.md

Guidance for Claude Code (claude.ai/code) working in this repository.

## What this is

`cachestore` is one cache abstraction (`CacheStore`, `MemoryStore`, a Redis store, and a
Redis-to-memory fallback), implemented per language in a pnpm + Turborepo + Changesets monorepo.
`SPEC.md` is the behaviour contract every implementation follows.

```
SPEC.md                         language-neutral contract and conformance cases
packages/cachestore-go/         Go core module: interface, MemoryStore, Fallback, JSON helpers.
                                No third-party dependencies, deliberately.
packages/cachestore-go/redis/   Go module: RedisStore and New. Separate so a service that never
                                uses Redis never pulls a Redis client.
.github/                        workflows, release scripts, publish configs, templates
.ai/                            skills and references (the source of truth for process)
```

Each Go module has a `package.json` next to its `go.mod`: a version-tracking shim whose scripts
(`build`, `lint`, `check-types`, `test`) call the Go toolchain so Turborepo and Changesets treat it
like any package. It is never published to npm.

## Commands

```sh
pnpm install
pnpm turbo run build lint check-types test      # everything
cd packages/cachestore-go && go test -race ./...  # one module
pnpm changeset                                   # interactive; agents write the file by hand
```

Go resolves both modules locally through the root `go.work`. Anything that must behave as a
consumer sees it (a release build) uses `GOWORK=off`.

## Rules that are easy to get wrong

- **Behaviour changes start in `SPEC.md`** and land in every implementation with conformance tests.
- **The core Go module must not gain a third-party dependency.** Put it in a separate module.
- **One issue = one PR** (`CONTRIBUTING.md`); branch `<type>/<issue-number>-short-description`.
- **A change to a module needs a changeset**, written by hand (`.changeset/<slug>.md`); a
  README-only change needs none and starts no workflow.
- **Never hand-edit** `.changeset/config.json`'s `ignore` list; it is generated by
  `node .github/scripts/sync-changeset-ignore.mjs --write`.
- **A cache error must never fail a request.** Treat `Get` errors as misses; never put a secret in
  a key (hash it).
- The redis module pins a *released* core version; bump it deliberately after core releases (see
  commit-strategy). Never pin a tag that does not exist.
